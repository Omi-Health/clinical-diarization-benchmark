# NVIDIA models on one L4: run record, 24 September 2026

24 September 2026. Fifteen frozen PriMock consultations, 2.4152 hours, one NVIDIA L4 in Frankfurt, one recording at a time. Seven native baseline configurations and five Omi configurations completed all 15 files, with each model’s pinned checkpoint; Nemotron 3 Diarization uses the released checkpoint below.

## Main comparison

Use automatic speaker counts and DER at ±250 ms in the compact tables. The full results retain strict zero-tolerance DER, both scoring panels, and all tested settings. No supplied two-speaker count, top-two selection or folding is used in the headline NVIDIA rows.

Whole recordings are the primary panel. Muse only has independently requested intervals, so it appears in a separate shared-interval comparison. Known-two API results and custom two-speaker folding are supplementary; they are not native automatic results. The fold ranks labels by duration and maps every extra label into the second retained label; it does not compare voices.

References are PriMock TextGrid turns intersected with Silero VAD, not adjudicated speaker truth. This small, repeatedly used two-speaker set does not establish accuracy for eight-person clinical meetings. Runtime choices were developed on this cohort; this is not a held-out qualification.

## Timing and Omi rows

One whole-recording warmup in the same process is excluded. GPU operations are synchronized around each inference call. Headline batch time combines each measured inference duration with its separately measured decoding duration, then takes the median; output serialization and model loading are excluded. The native streaming-preset times likewise include the separately measured official decoding pass. Individual timings are preserved in the snapshot.

Omi rows use the same weights without retraining, with proprietary runtime settings and automatic speaker counts. Nemotron 3 Diarization strict DER is 12.720% → 13.203%, versus 4.803% → 3.174% at ±250 ms. The evaluation collar is not a runtime parameter.

Omi live rows score delivered speaker revisions; native streaming presets score the completed-file output. Replay is unpaced and measures throughput, not user-facing latency or concurrent-stream capacity. Public outputs include the scored timelines reconstructed from delivered revisions. Runtime code, settings and raw live traces remain private. Rescoring verifies the saved timelines, not the private inference or delivery process.

## Reproduce

First fetch and verify the Git LFS audio as described in [reproduction](REPRODUCING.md).

```bash
python scripts/verify_ga.py
# GPU environment: inference/Dockerfile.ga
python -m inference.run_frozen_baseline --arm ga_off_bf16 --output private/ga-batch
python -m inference.score_run --output private/ga-batch
python -m inference.run_frozen_baseline --arm ga_stream_bf16 --output private/ga-streaming
```

The same command accepts `ga_off_fp32`, `v21_off_fp32`, `v21_stream_fp32`, `v1_whole_bf16` and `v1_win_fp32`. Each selects the pinned checkpoint, precision and geometry from the run receipt. Windowed v1 output includes stitching artifacts and is not a headline automatic-count result.

The public helper was verified from a clean clone on an NVIDIA L4 with `Dockerfile.ga`: all six non-windowed native arms completed, regenerated hypotheses were identical to the saved public outputs for every recording, every recomputed score matched the snapshot exactly, and inference medians were within 3 % of this run's host ([receipt](../results/ga-20260924/repro_20260924.json)). Its `wall_s` is inference-only; the published batch table additionally includes the official decoding measurement recorded separately.

Saved speaker/timestamp outputs for every scored view, including Omi runtime variants, are in `data/scored_outputs/ga-20260924/`. Native baseline files also remain in `data/hypotheses/ga-20260924/`. `verify_ga.py` recomputes all 7,000 per-recording scores, checks output hashes and verifies timing arithmetic. This is repeated scoring of the same 15 recordings. Outputs contain no transcript text, probabilities, runtime configuration or implementation code.

Provider API outputs and their verification scripts are separate; no vendor API requests were part of this run.
